# Aurora 系统架构与模块边界

## 1. 定位

本文是 Aurora 第一版系统职责、输入输出和依赖关系的长期正式视图。详细治理原则以[架构规范](<../../Aurora 架构规范.md>)为准；本文把已批准的五大边界整理为项目可维护结构。ADR-002、ADR-004、ADR-005 和 ADR-006 已于 2026-07-29 完成评审并成为 `accepted / not-started`；它们开始约束对应设计与未来实现，但不表示模块、协议、缓冲或自动检查已经存在。

## 2. 五个逻辑系统

| 系统           | 主要输入                                   | 权威职责与输出                                                                                    | 明确非职责                                             |
| -------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| SDK            | 宿主配置、浏览器/框架信号                  | 安全采集、规范化、隐私处理、采样、队列与标准事件上报                                              | 不做服务端聚合、Source Map 解析、权限或告警评估        |
| 数据接入       | SDK 批次、客户端上报密钥                   | 鉴权、来源/环境、大小/限流、运行时协议校验、可靠接收和逐项结果                                    | 不在请求内执行问题聚合、指标计算或告警                 |
| 数据处理与存储 | 已可靠接收事件、发布/Source Map 与策略投影 | 幂等事件事实、清洗、问题聚合、代表样本、指标、Source Map、告警评估、保留/删除和公开 Query/Command | 不成为账号、组织、Session 或平台角色权威               |
| 管理平台       | 浏览器用户请求、公开服务能力               | 身份/Session、组织项目治理、权限、平台领域 Command/Query、SPA 展示和获授权跨系统组合              | 浏览器不直连数据库、队列、对象存储内部键或处理私有实现 |
| 公共协议       | 已批准协议规则                             | 事件类型、枚举、限制、版本、运行时 Schema、兼容转换和契约样本的唯一来源                           | 不含采集、网络、数据库、页面或领域副作用               |

这些是逻辑与代码边界，不等于五个独立部署单元。第一版可以合并部署相关服务，但不能共享私有实现来绕过公开边界。物理服务拆分、数据库、队列和区域选择分别属于 `requires-accepted-adr`。

## 3. 核心数据流

1. SDK 只通过数据接入公开入口发送符合公共协议的事件；
2. 数据接入完成必要同步校验并写入可靠缓冲后，才返回“已接收”；
3. 数据处理异步形成事件事实、问题、指标、Source Map 结果和告警；
4. 管理平台后端通过处理系统公开 Query/Command 组合业务投影；
5. SPA 只调用平台公开 API，并按分区表达 `partial`、`stale` 和 `unavailable`；
6. 发布、权限、策略和删除等跨系统动作通过版本化状态、幂等上下文和可靠任务传播，不使用浏览器拼接或分布式事务伪装原子性。

“已接收”只表示可靠缓冲，不表示问题已生成或指标已可查询。任何状态、采样、水位和完整性必须由权威服务返回，前端不得从有限样本反推。

## 4. 依赖方向

- 公共协议位于依赖底层，不依赖业务系统；
- SDK Core 不依赖 Browser、插件或框架；Browser 只通过公开接口依赖 Core/协议；插件和框架适配只能依赖公开 Core、Browser 与协议；
- 服务端不得依赖 SDK 私有代码；
- 管理平台前端不得导入数据库模型、服务端私有领域对象或内部队列类型；
- 跨包只允许公开入口，禁止 `src`、`internal` 和未导出深层路径；
- 依赖自动检查原则由 accepted ADR-006 约束，首期工具入口由 accepted ADR-007 和 [Monorepo 与基础工程工具](monorepo-and-build.md)定义；当前仍无实现结果。

## 5. 跨系统不变量

- 外部输入一律视为不可信并运行时校验；
- SDK 最高优先级是不影响宿主页面；
- 可靠接收后不得静默丢弃，重试、重复投递和消费者恢复必须幂等；
- 平台权限提示不是 Command 授权，所有写操作重新鉴权；
- 密钥、令牌和一次性秘密只按最小范围使用，不进入日志或普通缓存；
- 数据删除必须跨存储确认，不能把部分清理描述为完成；
- 同一业务或协议只允许一个当前权威来源，缓存和投影必须携带来源、版本、水位与陈旧语义。

## 6. 当前正式化边界

已形成正式文档的部分包括 SDK、管理平台前后端、部署、测试、发布、恢复和 A5 数据生命周期。数据接入物理架构、处理/存储架构和事件协议仍缺少 accepted ADR、容量证据或机器 Schema，状态分别为 `requires-accepted-adr`、`requires-benchmark` 和 `deferred`；本轮不创建空壳文档。公共协议已实施为真实私有包 `@aurora/event-schema`：版本化公共信封、运行时边界校验、稳定错误、共享契约样本、错误事件协议契约第一增量（JavaScript 运行时错误、未处理 Promise 拒绝和资源加载错误正文、错误信封解析器与错误契约样本）与请求事件协议契约第一增量（请求方法/结果常量、安全请求正文、请求信封解析器与请求契约样本）已经存在；性能、通用资源、行为事件正文、批次/接收协议与请求采集插件仍不存在。真实 SDK 包现包括 `@aurora/core`、`@aurora/browser` 与 `@aurora/plugin-error`：Browser 的浏览器环境能力与页面生命周期基础第一增量、错误源订阅能力与请求观测能力第一增量（安全 fetch/XHR 观测、请求事实投影、共享代理 + 引用计数与宿主恢复）已经实现，错误插件第一增量已经实现；请求采集插件、性能/资源/行为插件、传输与框架适配仍不存在。
