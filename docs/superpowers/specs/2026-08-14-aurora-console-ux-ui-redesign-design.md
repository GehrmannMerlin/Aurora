# Aurora Console UX/UI 全面重设计

## 1. 定位、授权与当前状态

本文记录 Aurora Console 第一版管理平台 A1—D2 的新视觉与交互设计。用户在查看现有工作空间、组织工作空间、项目概览、通知中心、账号安全和登录页面的真实浏览器截图后，明确授权重新设计整个前端 UX/UI，并要求保留此前已经敲定的功能需求。

用户于 2026-08-14 依次批准以下方向：

1. 视觉方向 A：`Calm Observability`；
2. 导航方向 A：窄全局栏与有标签的上下文侧栏；
3. 内容密度 A：平衡证据密度，以状态、关键证据和行动为主；
4. 认证方向 A：桌面品牌侧栏与聚焦表单，窄屏收拢为单列；
5. 第 1 章“视觉系统与应用壳层”；
6. 第 2 章“页面族与信息架构”；
7. 第 3 章“状态、交互与适配标准”。

用户于 2026-08-14 完成整体最终批准。本文现为 `approved`，是新的视觉实施依据。它不改变任何 Route Target、业务规则、权限、安全模型、数据生命周期、Query/Command、API 或协议；代码已在 feature branch 实施、尚未部署，最终移动矩阵与整合复验仍为 partial，不能宣称完整发布验证通过。

## 2. 替代关系与长期权威边界

本文批准后：

- 替代 [Aurora 管理平台控制台视觉语言设计](2026-07-30-aurora-console-visual-language-design.md) 中的琥珀橙侧栏、顶栏结构、颜色、形状、密度和相关视觉条款；
- 替代 [Aurora Console 顶栏作用域菜单与固定侧栏优化设计](2026-08-14-console-navigation-shell-polish-design.md) 中依赖原深色顶栏、琥珀橙侧栏和顶栏组织/项目菜单的视觉与壳层条款；
- 不替代 [Aurora 第一版管理平台前端 UX/UI 设计](2026-07-27-aurora-frontend-ux-ui-design.md) 中 A1—D2、`NAV-A`、`AUDIT-A`、权限、页面状态、用户流程和业务边界；
- 不替代核心 PRD、平台产品业务域、Platform OpenAPI、Session、Navigation Context 或后端授权目标。

两个被替代的视觉设计文档保留历史原文、标记为 `superseded`，并反向链接本文。历史实现计划继续作为已发生工作的证据，不再作为新视觉实现依据。

## 3. 问题定义

现有浏览器页面虽然基本呈现了导航和内容入口，但存在以下系统性问题：

1. 大面积高饱和琥珀橙侧栏压过业务内容，无法形成安静、可信的监控工作区；
2. 顶栏同时承担品牌、全局入口、组织和项目选择，范围与导航语义拥挤；
3. 页面主体缺少稳定的信息层级，标题、状态、证据和操作像未经设计的原始文本；
4. 空状态常表现为大片空白，既不解释原因，也不提供真实下一步；
5. 原始英文状态键直接成为主文案，影响理解并暴露内部实现细节；
6. 登录等公开页面错误复用了登录后的项目控制台壳层；
7. 表单、列表、导航和反馈缺少统一密度、焦点、错误与窄屏行为；
8. 页面空间利用失衡：少量内容被挤在左上角，大屏其余区域没有结构意义。

本次重设计以统一系统解决这些问题，不通过逐页添加装饰卡片或虚构数据掩盖结构缺陷。

## 4. 设计目标与非目标

### 4.1 目标

1. 建立“状态 → 证据 → 行动”的稳定阅读顺序；
2. 明确区分全局导航、组织上下文和项目上下文；
3. 让列表、详情、表单、诊断和空状态形成可复用页面族；
4. 在中高信息密度下保持平静、清晰和可扫描；
5. 让数据完整性、采样、限流、降级、新鲜度和不可用状态成为一等信息；
6. 支持桌面、平板、移动、键盘、屏幕阅读器、200% 缩放和减少动态效果；
7. 所有视觉元素均可追溯到真实业务对象、数据、权限或操作。

### 4.2 非目标

本次设计不引入：

- 全局搜索、命令面板或快捷启动器；
- 暗色主题、组织自定义主题或项目品牌色；
- 项目健康分、预测、排行榜、推荐卡片或 AI 诊断；
- 没有正式契约支撑的统计、趋势、图表或实时更新；
- 邮件、短信或外部通知设置；
- 新页面、新路由、新业务对象或新权限；
- 对现有 API、Session、Navigation Context 或数据生命周期的修改。

## 5. 视觉方向：Calm Observability

### 5.1 视觉原则

控制台采用单一浅色主题和克制的开发者工具气质：

- 深石墨窄全局栏承担稳定应用骨架，不再使用横向深色顶栏压缩作用域入口；
- 冷灰上下文侧栏承担范围与导航，不使用大面积品牌橙色；
- 主画布使用冷白/浅灰，工作表面使用白色；
- 钴蓝只用于主操作、链接、当前项和焦点；
- 成功、警告、危险与信息状态使用独立语义色，并同时配合文字和图标；
- 普通内容依赖对齐、边界和间距建立层级，不堆叠悬浮卡片；
- Console 正式表面不使用装饰性渐变、玻璃拟态、噪点或光晕。

### 5.2 颜色令牌候选基线

| 令牌 | 基线值 | 用途 |
|---|---:|---|
| `color.rail.background` | `#101828` | 全局窄栏 |
| `color.rail.foreground` | `#F9FAFB` | 全局栏文字和图标 |
| `color.rail.muted` | `#98A2B3` | 全局栏次要状态 |
| `color.context.background` | `#F2F4F7` | 组织/项目上下文侧栏 |
| `color.page.background` | `#F7F8FA` | 页面画布 |
| `color.surface.background` | `#FFFFFF` | 列表、表单、详情和证据表面 |
| `color.border.default` | `#D0D5DD` | 普通边界 |
| `color.text.primary` | `#101828` | 标题和主正文 |
| `color.text.secondary` | `#475467` | 辅助说明和元数据 |
| `color.action.primary` | `#3157D5` | 主操作、链接、当前项和焦点 |
| `color.status.success` | `#067647` | 已确认成功或正常事实 |
| `color.status.warning` | `#B54708` | 已确认风险或降级事实 |
| `color.status.danger` | `#B42318` | 错误、危险和破坏性事实 |
| `color.status.info` | `#175CD3` | 中性信息与处理中事实 |

实施阶段可以在同一视觉关系内对数值做小幅无障碍校正，但不得重新引入琥珀橙整面侧栏或用语义色承担普通导航。

### 5.3 字体、形状与间距

- 正文和 UI 使用本地系统无衬线栈，优先 `system-ui`、`Segoe UI`、`PingFang SC`、`Microsoft YaHei` 和兼容回退；不依赖外部 Web Font；
- 对象 ID、时间戳、状态键、请求编号和代码片段使用 `Cascadia Mono`、`JetBrains Mono`、`SFMono-Regular` 等等宽回退；
- 等宽字体不用于标题、普通正文、按钮或整张表格；
- 基础间距使用 `4 / 8 / 12 / 16 / 24 / 32 / 40px`；
- 常规控件高度 40px，紧凑工具栏控件最低 36px，触控环境满足至少 44px 的可操作目标；
- 控件圆角 8px，普通工作表面 10—12px；
- 普通表面不使用悬浮阴影，Dialog、Drawer、Popover 等真实浮层使用统一轻量阴影；
- 不使用超大营销标题或夸张圆角。

## 6. 应用壳层与导航

### 6.1 桌面壳层

桌面登录后壳层由四个稳定区域组成：

```text
┌────────┬──────────────────────┬────────────────────────────────────┐
│ 全局栏 │ 上下文侧栏           │ 页面工具区                         │
│ 64px   │ 组织/项目 220—240px  ├────────────────────────────────────┤
│        │                      │ 独立滚动的主内容区                 │
└────────┴──────────────────────┴────────────────────────────────────┘
```

- 全局栏固定在视口左侧，宽度目标 64px；
- 上下文侧栏只在当前组织或项目需要时出现，宽度目标 232px；
- 页面工具区显示安全面包屑、页面标题、范围状态和真实页面操作；
- 主内容区独立滚动，导航不随长页面滚走；
- 页面标题与首屏主要证据在正常桌面高度下可见；
- 不增加无真实能力支撑的搜索框。

### 6.2 全局栏

全局栏固定承载：

1. Aurora 品牌入口；
2. 工作空间；
3. 站内通知与服务端账号级未读状态；
4. 账号入口；
5. 仅后端确认的平台管理员可见的平台资源策略入口。

当前项同时通过形状、图标/标签、`aria-current` 和焦点状态表达，不只依赖颜色。桌面窄栏图标必须具有可访问名称，并通过 Tooltip 或展开行为提供可读标签。

### 6.3 上下文侧栏

组织上下文分组：

- 项目；
- 成员；
- 设置；
- 用量；
- 管理令牌；
- 安全审计；
- 回收站。

项目上下文分组：

- 接入：SDK 接入；
- 观测：概览、问题、请求、性能、数据状态；
- 交付：发布、Source Map；
- 告警：规则、实例；
- 治理：成员、客户端密钥、设置、归档与删除。

分组仅改变视觉组织，不合并页面、对象或 Route Target。无权入口由后端能力投影决定隐藏或禁用；不得由前端复制角色矩阵。

### 6.4 范围切换

- 当前组织或项目显示在上下文侧栏顶部的范围控件中；
- 范围控件使用 Navigation Context 返回的安全名称与授权目标；
- 选择组织使用组织 `entry` 目标，选择项目使用项目 `entry` 目标；
- 切换前执行现有范围清理边界，清除旧范围缓存、临时选择和不兼容查询；
- 空集合、目标失效、无权和服务不可用使用权威状态，不拼接任意 URL；
- 窄屏范围选择位于统一导航 Drawer 内。

### 6.5 无上下文页面

工作空间入口、通知中心和账号中心不显示虚假的组织或项目侧栏。平台资源策略使用独立平台管理员上下文。登录、注册、找回密码和公开邀请确认不渲染登录后壳层。

## 8. 代表页面结构

### 8.1 B1 工作空间、组织和项目入口

1. 页面工具区显示“工作空间”、简短业务说明和“创建项目”主操作；
2. 组织选择作为清晰范围控件，不与全局导航文字混排；
3. 项目使用紧凑行列表或列表式卡片，展示安全名称、技术栈、生命周期状态和授权入口；
4. B1 只承担范围选择，不增加项目健康分、请求量、趋势或排名；
5. 无组织、无项目和无权限分别使用真实空状态与授权下一步；
6. 组织范围存在时显示组织上下文侧栏，但主内容仍保持项目入口职责。

### 8.2 C2 项目概览

C2 使用“状态 → 证据 → 行动”的三段结构：

1. 状态：权威数据接收状态、文字原因、服务端时间和最近更新时间；
2. 证据：问题、重要告警、请求、性能和数据可信度中已有正式 Query 支撑的事实；
3. 行动：只显示后端授权且当前可执行的接入、诊断或查看目标。

C2 不展示趋势图、健康评分、预测、排名、推荐操作卡片或装饰性统计。视觉探索稿中的趋势区域只用于比较密度，不进入正式设计。

### 8.3 D1 站内通知中心

1. 页面只使用全局栏和受控宽度单列列表；
2. “全部/未读”是写入 URL 的二选一筛选；
3. 每行展示安全标题/摘要、类型、最小组织/项目上下文、服务端时间、已读状态和目标可用性；
4. 支持打开后端授权目标和单条标记已读；
5. 不增加全部已读、标记未读、删除、批量选择、线程或通知偏好；
6. “没有通知”和“没有未读通知”使用不同空状态文案。

### 8.4 A5 账号安全、修改密码与注销

1. 使用全局栏，不显示项目导航；
2. 内容使用受控阅读宽度，按修改密码、退出当前会话和注销账号纵向分区；
3. 常规操作、会话操作和不可逆危险操作具有不同层级；
4. 注销完整表达 7 天冷静期、双重身份复核、受理后 Session 终止和数据生命周期，不缩减为普通红色按钮。

### 8.5 A2 登录与认证页面

桌面认证外壳使用品牌侧栏与聚焦表单：

- 品牌区约占视口宽度 40%—45%，使用深石墨纯色表面、Aurora 标识、简短价值说明和低对比装饰性轨道图形；
- 表单区使用浅色背景，表单最大宽度约 420px；
- 表单只展示当前流程需要的字段、主操作和批准的辅助入口；
- 认证页不展示工作空间、组织、项目、通知或账号安全导航；
- 小于 640px 时移除大型品牌侧栏，保留紧凑品牌页头和单列表单；
- 错误就近显示，提交只锁定当前表单，不改变布局宽度。

装饰图形不得表达不存在的系统状态、指标或实时数据。

## 9. 公共状态系统

所有页面及可独立查询的区域统一覆盖：

| 状态 | 呈现规则 |
|---|---|
| `loading` | 使用与真实结构一致的骨架；切换账号、组织或项目时不闪现旧范围数据 |
| `empty` | 解释为什么为空和真实下一步；不以大片空白或假示例填充 |
| `error` | 失败区域就近说明并重试；不覆盖其他已成功区域 |
| `forbidden` | 不泄露对象名称、数量、成员、策略或安全上下文 |
| `processing` | 只锁定当前提交、行或按钮，不阻塞整页 |
| `partial` | 逐项标记缺失字段、统计口径、授权目标或不可用操作 |
| `stale` | 显示数据截止时间和刷新入口，不把缓存写成最新事实 |
| `unavailable` | 说明服务不可用，不从其他页面或本地状态重建权威结果 |
| `conflict` | 展示服务端当前版本，保留或安全处理草稿并要求重新确认 |
| `propagating` | 区分 Command 已保存与数据面已经应用 |
| `archived` / `deleted` | 保留批准的只读、返回和安全退出行为 |

未知数量、不可用指标或不完整未读数显示“不可用”或“—”，不得显示为 `0`。

## 10. 状态文案与技术详情

稳定后端键不直接作为页面主文案。UI 使用可理解的中文语义，例如：

| 稳定键 | 主文案示例 |
|---|---|
| `not_receiving` | 尚未接收到数据 |
| `no_received_events` | 当前项目还没有已接收事件 |
| `batch_partial` | 部分操作未完成 |

原始状态键、请求编号、对象 ID 和诊断代码只在“技术详情”中以等宽字体显示。所有时间明确标注当前业务时区或 UTC，不展示语义不明的裸时间。

## 11. 列表、表格与筛选

1. 允许恢复的筛选、排序和分页写入 URL；
2. 服务端分页、总量、排序、UTC 边界和规范化查询保持权威；
3. 加载时保留表头和稳定列宽，避免页面跳动；
4. 当前页选择只在当前会话有效，查询、分页或范围变化立即清空；
5. 行主入口和高风险操作分离，高风险操作不隐藏在整行点击中；
6. 空结果、部分结果和请求失败严格区分；
7. 窄屏优先保留身份、状态和主操作，其余列通过横向滚动或详情 Drawer 访问；
8. 不提供未经业务批准的跨页选择、全结果选择、批量后台任务或持久化选择。

## 12. 表单与 Command

1. 标签始终可见，不使用 placeholder 代替字段名；
2. 前端只执行公开契约允许的格式和基础组合校验；权限、冲突、版本和业务约束由服务端权威判断；
3. 字段错误就近显示，表单级错误位于表单顶部，提交失败不清空输入；
4. 保存成功后重新查询权威状态，高风险操作不做虚假乐观更新；
5. 删除、归档、注销、轮换密钥、降低策略上限等操作使用明确确认流程；
6. 禁用操作同时解释原因，不能只降低透明度；
7. 一次性密钥只在服务端确认的单次结果中展示，并提供明确复制反馈；
8. 多版本冲突不自动合并旧草稿与新权威值。

## 13. 数据可信度与图表

涉及指标或图表的页面必须同时表达：

- 查询时间范围和服务端数据截止时间；
- 采样、限流、降级和数据缺档；
- 聚合分辨率、单位、公式和统计口径；
- 部分结果、缺失原因和不可用原因。

图表只出现在已有正式时间序列契约支持的 C5、C6 等页面。前端不连接缺失时段，不从有限样本生成权威趋势，不用占位图表表达无数据。关键数据提供可读取的文字摘要或表格替代。

## 14. 响应式布局

| 视口 | 壳层行为 |
|---|---|
| `≥ 1280px` | 完整全局栏、上下文侧栏和主工作区 |
| `960—1279px` | 全局栏保留，上下文侧栏可折叠，主工作区保持阅读宽度 |
| `< 960px` | 全局与上下文导航合并为遮罩 Drawer；管理焦点并返回触发按钮 |
| `< 640px` | 表单单列、页面操作堆叠、摘要纵向排列；认证页使用紧凑品牌页头 |

主内容使用适合阅读的最大宽度；列表、表格和诊断工作区可以按业务需要使用更宽画布。布局不得依赖固定桌面宽度或水平溢出隐藏关键操作。

## 15. 无障碍、动效与反馈

### 15.1 无障碍

- 文本、图标、边框和状态颜色满足 WCAG AA 对比度；
- 所有功能支持键盘，并具有清晰 `:focus-visible`；
- 颜色不是状态的唯一表达，状态同时包含文字与必要图标；
- 图标按钮提供可访问名称，字段错误通过语义关系关联输入；
- 使用正确标题层级、导航、主区域、Dialog、Drawer 和状态播报；
- 200% 缩放不丢失内容或操作；
- 长中文文案、长项目名、对象 ID 和技术标识不会破坏布局。

### 15.2 动效

- 菜单、Drawer、状态切换和轻量反馈使用 150—220ms 动效；
- 不使用连续漂浮、脉冲、滚动驱动或装饰性大型动画；
- 支持 `prefers-reduced-motion`，减少或关闭非必要动效；
- 动效不延迟权威状态或 Command 结果呈现。

### 15.3 操作反馈

- Toast 只用于短暂成功确认；
- 需要处理的错误保留在对应区域；
- 行级处理不阻塞其他列表行；
- 成功反馈不提前宣称异步传播、邮件送达、告警恢复或数据面生效。
