# Aurora Console 顶栏作用域菜单与固定侧栏优化设计

## 1. 定位与批准状态

本文收口 Aurora Console 已批准 `NAV-A` 分层上下文壳层的低风险视觉与交互细节。用户于 2026-08-14 根据公网 Preview 截图指出：组织/项目标签与原生选择框并排、顶栏与侧栏缺少明显当前项、侧栏未占满可视高度且随内容滚动、导航行过密且文字未居中。用户已明确批准本文推荐设计。

本文不新增、删除或重排业务页面，不改变 Route Target、权限、Session、Navigation Context、Query/Command、数据口径或生命周期规则。它只优化现有顶栏作用域选择和侧栏壳层表现。

## 2. 设计目标

1. 组织和项目选择成为各自顶栏入口的一部分，不再显示为入口右侧的独立表单控件；
2. 顶栏与侧栏都明确表达当前导航或作用域，且不只依赖颜色；
3. 所有桌面组织/项目页面使用满高固定侧栏，右侧内容独立滚动；
4. 侧栏条目获得均衡密度、居中文字和一致选中态；
5. 保持键盘、屏幕阅读器、触屏和窄屏 Drawer 可用；
6. 继续遵守深石墨顶栏、纯色琥珀橙侧栏、浅色内容区、蓝色选中标识和禁止渐变规则。

## 3. 候选方案与结论

### 3.1 方案 A：锚定式作用域菜单（采用）

“组织”和“项目”分别成为一体化顶栏菜单按钮。按钮显示入口名称、当前对象名称和展开指示，点击后在按钮正下方打开锚定菜单。菜单使用 Navigation Context 已投影的组织、项目和安全 Route Target。

优点：导航语义清楚，不再像额外表单；键盘、触屏和小屏行为一致；可准确表达当前作用域并复用公开导航目标。代价：需要实现菜单焦点、关闭和定位状态。

### 3.2 方案 B：Hover 与点击混合菜单（不采用）

桌面鼠标悬浮或点击均打开，触屏仍使用点击。优点是鼠标路径短；缺点是容易误触、菜单穿越不稳定，并产生两套触发语义。第一版不引入该复杂度。

### 3.3 方案 C：标签内嵌原生 Select（不采用）

将标签和原生 `select` 包进一个视觉容器。改动较小，但仍保留表单控件观感，无法解决“顶栏入口与当前作用域割裂”的核心问题。

## 4. 顶栏信息架构

顶栏入口顺序保持不变：

```text
Aurora | 工作空间 | 组织 [当前组织] ▾ | 项目 [当前项目] ▾ | 通知 | 账号安全
```

- `Aurora` 保持品牌入口；
- “工作空间”“通知”“账号安全”保持真实 Route Target 链接；
- “组织”“项目”是作用域菜单按钮，不再额外渲染并列 `<select>` 或重复当前组织名称；
- 当前组织/项目存在时显示安全名称；不存在时显示“选择组织”或“选择项目”，不伪造对象；
- 未选择组织时项目菜单不可列出跨组织项目；它展示明确说明，不用仅降低透明度表示不可用；
- 顶栏当前入口使用纯色背景变化、底部蓝色 3px 标识和 `aria-current`/展开状态共同表达；
- 工作空间路由激活“工作空间”，组织路由激活“组织”，项目路由激活“项目”，通知与账号路由分别激活自身入口。

## 5. 作用域菜单交互

### 5.1 打开与关闭

- 鼠标或触屏点击按钮打开菜单；再次点击关闭；
- 键盘 `Enter` 或 `Space` 打开，`Escape` 关闭并把焦点还给触发按钮；
- 点击菜单外关闭；路由变化后关闭；
- 同一时间最多打开一个作用域菜单；
- 第一版不以 Hover 作为打开条件，避免误触和触屏语义分叉。

### 5.2 菜单内容

- 组织菜单只展示 Navigation Context 返回的可访问组织；
- 项目菜单只展示当前组织中的可访问项目；
- 当前项具有可读“当前”标记及 `aria-current`，不只依赖底色；
- 空集合显示真实空状态；不生成假组织、假项目或禁用占位项；
- 菜单列表过长时在浮层内部滚动，不扩大顶栏高度。

### 5.3 选择结果

- 选择组织使用该组织的 `entry` Route Target；
- 选择项目使用该项目的 `entry` Route Target；
- 前端不拼接任意 URL，不复制服务端角色判断；
- 导航前沿用现有作用域清理边界，清除旧作用域缓存、临时选择和不兼容查询；
- 目标失效、无权或后端不可用时遵守现有安全退出和错误状态，不保留可操作的陈旧作用域。

## 6. 桌面壳层与滚动模型

桌面壳层采用固定视口布局：

```text
100dvh application shell
├─ 顶栏（固定高度）
└─ body（剩余高度，min-height: 0）
   ├─ 侧栏（固定宽度、满高、自身可滚动）
   └─ 主内容（独立纵向滚动）
```

- 应用壳层高度为 `100vh` 并优先使用 `100dvh`；外层禁止产生与主内容并行的页面滚动；
- 顶栏不随右侧内容滚动；
- 侧栏占满顶栏以下的全部高度，宽度保持当前视觉基线附近，不因页面内容高度收缩；
- 主内容区设置 `min-width: 0`、`min-height: 0` 和 `overflow-y: auto`；
- 侧栏项目超过可视高度时只滚动侧栏自身，右侧内容滚动不改变侧栏边界位置；
- 该模型统一应用于全部带组织或项目侧栏的桌面页面。

## 7. 侧栏导航视觉与状态

- 侧栏背景继续使用 `#D47A16` 纯色，不使用渐变、纹理、阴影或玻璃效果；
- 导航列表使用一致的上下内边距和约 6px 行间距；
- 每个导航目标高度为 48px，满足可访问目标尺寸并缓解当前过密问题；
- 链接在侧栏宽度内保留水平边距，文字水平和垂直居中；
- 当前路由使用 `#FFF4DC` 纯色背景、深色文字、左侧 `#1D4ED8` 3px 标识和 `aria-current="page"`；
- 左侧标识使用定位层，不通过不对称边框挤偏居中文字；
- Hover 使用同方向纯色明度变化；Focus visible 使用清晰蓝色焦点环；
- 组织侧栏和项目侧栏共享同一状态模型，不创建页面私有变体。

## 8. 响应式行为

- `1024px` 以下继续隐藏桌面侧栏并使用可关闭导航 Drawer；
- Drawer 复用同一条目顺序、当前项、颜色和居中规则；
- 顶栏在窄屏允许把作用域选择合并进 Drawer 或受控弹层，但不得恢复为并排原生选择框；
- 窄屏菜单和 Drawer 必须支持关闭、焦点恢复与滚动锁定；
- 响应式调整不隐藏权限、生命周期、完整性或危险说明。

## 9. 组件边界

- `TopBar`：决定全局入口顺序和基于当前路由的顶栏激活状态；
- 作用域菜单组件：分别封装组织/项目触发器、菜单状态、键盘/焦点和 Route Target 选择；
- `LayeredSidebar`：只消费当前路由和现有侧栏条目，输出统一当前项语义；
- `AppShell`：拥有固定视口、桌面侧栏和主内容滚动边界；
- `AppLink`：继续提供统一链接与 `aria-current`，其选中样式不得让顶栏和侧栏互相污染；
- Navigation Store：只在现有公开 Navigation Context 范围内提供当前组织、当前项目及安全条目投影；不新增持久化状态或权限规则。

## 10. 错误与边界状态

- Navigation Context `loading` 时菜单触发器保持稳定尺寸并显示加载语义，不闪现旧对象；
- `unavailable` 时不展示陈旧组织/项目选项，顶栏保留工作空间、通知和账号安全等当前可证明安全的入口；
- 没有当前组织时不展示当前项目；
- 当前项目不属于当前组织投影时视为失效上下文，使用现有安全退出目标；
- 路由切换期间菜单关闭，避免浮层覆盖新页面；
- 菜单项导航失败时保留可读错误状态，不乐观标记已切换。

## 11. 测试与验收

### 11.1 组件测试

- 顶栏不再渲染独立并列的组织/项目原生选择框；
- 点击、`Enter`、`Space` 打开菜单，`Escape` 和外部点击关闭；
- 当前组织/项目名称与 `aria-expanded`、`aria-controls`、`aria-current` 正确；
- 选择组织/项目使用真实 Route Target 并触发现有作用域清理；
- 工作空间、组织、项目、通知和账号路由显示正确顶栏当前项；
- 侧栏当前路由具有 `aria-current="page"`，非当前项没有；
- Navigation Context 空、加载和不可用状态不泄露陈旧选项。

### 11.2 真实浏览器测试

- 通过真实点击和键盘从组织/项目菜单进入目标页面；
- 右侧内容滚动时，顶栏和侧栏的视口位置不变；
- 侧栏底部达到顶栏以下视口底部；
- 侧栏文字居中且导航行满足最小高度；
- 桌面和 Drawer 使用一致当前项；
- axe 无新增违规，焦点在菜单关闭后回到触发器。

### 11.3 视觉验收

- `1906 × 1014` 桌面视口覆盖用户截图对应场景；
- 组织回收站与项目概览各保留一张验证截图；
- 截图必须显示：一体化作用域入口、顶栏选中态、满高侧栏、均匀导航行、居中文字和侧栏选中标识；
- 禁止出现渐变、重复当前组织文本或组织/项目入口右侧的独立选择框。

## 12. 部署与回滚

- 只使用仓库受控 Preview 部署链发布到 `47.238.145.24`；
- 部署前运行 Console typecheck、单元/组件测试、生产构建、Playwright 与 axe；
- 部署后验证 `https://aurora.ah.cn/`、组织页面和项目页面的真实 HTTPS 行为；
- 保留前一成功 Release，若 Console 健康检查、路由、导航或视觉验收失败，使用现有 Preview 回滚流程；
- 本变更不包含数据库 Migration、公开 API 或服务端权限变化。

## 13. 非目标

- 不新增或重排顶栏、组织侧栏或项目侧栏业务入口；
- 不实现搜索型全局命令面板、最近访问、收藏或跨组织聚合；
- 不改变组织/项目选择权限或服务端 Navigation Context；
- 不引入暗色主题、主题切换、动画库或新的组件框架；
- 不修改业务页面数据、文案口径、Query/Command 或生命周期；
- 不把 Hover 作为第一版菜单打开条件。
